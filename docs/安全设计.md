# 安全设计（护栏清单）

这份文档说明：这套客服智能体防的是哪几类问题、每一层控制做了什么、怎么验证、以及
哪些明确**不在**范围内。所有条款都对应仓库里真实的代码与测试，没有"计划中"的项。

一条主线贯穿全部设计：**模型只提议，代码做决定（LLM proposes, code disposes）**。
任何一层护栏都在"模型被完全攻破"的前提下依然成立。

## 威胁模型

| 威胁 | 攻击者想干什么 | 为什么要防 |
|---|---|---|
| **提示词注入** | 让模型忽略政策，批准一笔不该批的退款（特价商品、超上限、别人的单、已退过） | 直接金钱损失 |
| **跑题滥用 / 烧 token** | 把客服机器人当免费通用助手（写代码、讲笑话、做题），或单纯灌流量 | 模型账单；真实客户体验下降 |
| **洪水式 DoS** | 对 `/api/chat` 打高频请求 | 服务不可用、账单失控 |

## 分层防御

### 一、提示词注入

| # | 控制 | 位置 | 挡住了什么 | 验证 |
|---|---|---|---|---|
| 1 | **用户确认与确定性复核**：模型只能准备申请；客户确认接口校验身份、快照、有效期与资格后，才在事务内写入退款或工单；会话锁、订单行锁与唯一索引防重复 | `app/refund_confirmation.py`、`app/policy/engine.py` | 咨询被误理解为申请、模型直接执行、旧卡片与并发重复执行 | `tests/test_refund_confirmation.py`（咨询、取消、过期、冒用、篡改、并发与无模型确认） |
| 2 | **加固的系统提示词**：明确职责范围、OWASP 式的"客户消息是数据不是指令"、固定的拒绝话术 | `app/agent/prompts.py` | 降低模型被诱导的**概率**，与第 1 条互补 | 人工：真实注入尝试；控制台时间线可见拒绝 |
| 3 | **注入特征检测**：正则 + 模糊匹配（`rapidfuzz` 近似比），能抓变形（`ignroe`、`i.g.n.o.r.e`）、零宽字符、疑似 Base64 载荷 | `app/agent/guard.py` | 在控制台把尝试标成 `injection_flag` 事件，并影响模型的拒绝姿态 | `tests/test_guardrails.py::test_guard_fuzzy_match_catches_obfuscations` |
| 4 | **输出校正**：模型本轮没有执行权限；宣称已退款时替换为系统更正，并记录原文供排查 | `app/agent/runner.py` | 用户被未执行的成功话术误导 | `tests/test_guardrails.py`、`tests/test_refund_confirmation.py` |
| 5 | **身份只来自 JWT，绝不来自对话**：客户身份在智能体运行前就固定，没有工具能改它，每个订单工具都校验归属；会话与主人绑定（他人会话 → 404）；管理端要求 `role=admin` | `app/auth.py`、`app/main.py`、`app/agent/tools.py` | 冒名（"我是 carol@example.com"）、劫持会话、偷看别人的对话 | `tests/test_tools.py::test_ownership_mismatch_is_refused`、`tests/test_guardrails.py::test_cannot_continue_another_customers_conversation` |
| 6 | **转人工也须客户确认**：只有符合基础条件但超自动审批金额的申请可进入待确认；确认后创建待审核工单，人工批准仍需独立管理权限 | `app/refund_confirmation.py`、`app/hitl.py` | 未授权创建工单、不合条件的订单进入审核、客户自行批准 | `tests/test_refund_confirmation.py`、`tests/test_hitl.py` |
| 7 | **工具返回值同样不可信**：商品名、类目、客户姓名邮箱等自由文本，用第 3 条的检测器扫描，读起来像指令的内容在进模型前被替换，并记 `injection_flag`（`source: "tool"`） | `app/agent/tools.py`（`untrusted_text`） | 间接注入：客户把账号名改成一段指令 | `tests/test_tools.py::test_instruction_like_stored_text_never_reaches_the_model` |
| 8 | **回复里不放可点链接和图片**：Markdown 链接渲染成"文字 + 明文 URL"，图片直接丢弃 | `frontend/src/components/Markdown.tsx` | 被诱导写出的钓鱼链接出现在可信 UI 里（尤其客服控制台） | 前端渲染逻辑，`Chat` 与 `Console` 共用该组件 |

> 第 1 + 第 4 条分别约束执行与输出：**执行侧**（工具调用）由确定性
> 代码裁决，**表达侧**（聊天输出）与执行结果核对。模型可以随便说，但不能**造成**非法状态。

### 二、成本与滥用

| # | 控制 | 位置 | 挡住了什么 |
|---|---|---|---|
| 9 | 单条消息长度上限（`MAX_MESSAGE_CHARS`，默认 2000）→ 400 并回显上限 | `app/main.py` | 提示词灌水、ReDoS 面、超长 prompt |
| 10 | 单会话轮次上限（`MAX_CONVERSATION_TURNS`，默认 30）→ 429 | `app/main.py` | 一个会话无限聊下去烧 token |
| 11 | 双预算：会话级 token 上限（默认 60000，行上原子计数）+ 每客户每 UTC 日上限（默认 300000，Redis）。任一触顶，下一轮直接礼貌拒绝，**不调模型** | `app/agent/runner.py`、`app/redis.py` | 成本硬上限 |
| 12 | LangGraph `recursion_limit`（默认 12） | `app/agent/runner.py` | 模型卡在工具循环里一次跑出几十个工具调用 |
| 13 | 每次模型调用都带 `max_tokens`（默认 1024） | `app/agent/llm.py` | 单次输出长度失控 |
| 14 | 每客户速率限制（Redis 固定窗口，多副本共享，默认 `10/minute`，按 JWT subject 计）→ 429 + `Retry-After`；未认证请求先 401、不计数 | `app/main.py`、`app/redis.py` | 单个客户刷爆（且不会因为共享 IP 连累别人） |
| 15 | 会话内串行（同时只允许一轮，冲突 409）+ 全局在飞上限（`MAX_CONCURRENT_TURNS`，超出 503 + `Retry-After`） | `app/main.py`、`app/redis.py` | 同一会话交错竞态；过载传导成上游 429 |
| 16 | 系统提示词里的范围规则 + 拒绝模板 | `app/agent/prompts.py` | 跑题对话（写诗、写代码、做题）白烧 token |

## 可调参数与默认值

全部可用环境变量覆盖（见 `.env.example`），启动时经 `get_settings()` 读取一次；
速率限制字符串按请求读取，便于测试覆盖。

| 变量 | 默认 | 超限后的表现 |
|---|---|---|
| `MAX_MESSAGE_CHARS` | 2000 | 400，detail 里带上限值 |
| `MAX_CONVERSATION_TURNS` | 30 | 429，"请开新对话" |
| `MAX_CONVERSATION_TOKENS` | 60000 | 礼貌拒绝，不调模型；`budget_exhausted` 事件 |
| `AGENT_RECURSION_LIMIT` | 12 | `error` 事件，本轮结束，不写退款 |
| `MAX_OUTPUT_TOKENS` | 1024 | 模型侧截断 |
| `CHAT_RATE_LIMIT` | 10/minute | 429 + `Retry-After`（按客户） |
| `CUSTOMER_DAILY_TOKEN_BUDGET` | 300000 | 礼貌拒绝，不调模型；`budget_exhausted` 事件 |
| `MAX_CONCURRENT_TURNS` | 200 | 503 + `Retry-After` |
| `TURN_TIMEOUT_S` | 120 | `error` 事件结束本轮 |

## 每种触发下用户看到什么

| 触发 | HTTP | 新增 SSE 事件 | 用户可见文案 |
|---|---|---|---|
| 消息超长 | 400 | 无流 | 提示超长并给出上限 |
| 会话轮次用尽 | 429 | 无流 | 提示开新对话 |
| 预算耗尽 | 200 | `budget_exhausted` + 最终 `message` | 礼貌拒绝并建议转人工 |
| 递归上限 / 模型报错 / 超时 | 200 | `error` 步 + `error` 事件 | 通用错误提示（细节只进日志） |
| 触发限流 | 429 | 无流 | 提示限流 + `Retry-After` |
| token 缺失或失效 | 401 | 无流 | 登录状态已过期 |
| 上一轮未结束 | 409 | 无流 | 上一条还在处理中 |
| 系统过载 | 503 | 无流 | 稍后重试 + 秒数 |
| 跑题 | 200 | 正常无工具回复 | 模型简短拒绝 |
| 无依据的批准话术 | 200 | `output_correction` | 原文前插入系统更正 |
| 疑似注入 | 200 | `injection_flag`（仅管理员可见） | 政策照常执行，控制台可见标记 |

所有新增事件类型由同一个 `ReasoningTimeline` 组件渲染，前端无需新增页面。

## 如何验证

```bash
# 单元/集成测试（SQLite + 进程内 Redis 替身，不需要 API Key）
cd backend && pip install -r requirements-dev.txt && python -m pytest -q

# 压测：AbusiveUser / RaceUser 探针会主动尝试越界，跑完用不变量脚本核对台账
python loadtest/check_invariants.py     # 非法批准必须为 0
```

检查台账任何时候都应满足：**不存在政策不允许的 `approved` 退款，不存在一单多退**。

## 明确不在范围内

- **用 LLM 做输入/输出分类器**：目前的启发式检测 + 确定性闸门已够用；若假阴性成为问题，
  加一次小模型分类调用是最自然的升级。
- **更严格的间接注入溯源**：当前不摄入外部内容（RAG 文档、网页抓取、邮件）；将来若加，
  分离规则与确定性闸门仍然成立，但应按来源加更严的标记体系。
- **模型配置的地址白名单**：能改模型地址的必须是不带 scope 的管理员，且这是自托管项目，
  本地/内网地址是常见用法，因此不做限制；若改成多人共享服务，应在此加白名单。
